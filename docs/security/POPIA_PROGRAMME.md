# POPIA programme outline (South Africa)

Working outline for responsible parties using 4DS. Legal advice required for your entity.

## Principles mapped to product

| POPIA theme | Product / ops control |
|-------------|------------------------|
| Accountability | Assurance profile + audit events |
| Processing limitation | Role portals; tenant isolation |
| Purpose specification | Incident / protection / store account kinds |
| Further processing | Document retention assumptions in profiles |
| Information quality | Profile fields; CRM corrections |
| Openness | Client portal visibility of own data |
| Security safeguards | MFA, throttling, evidence hashing, device security |
| Data subject participation | Profile edit; support for access/correction requests |

## Operator checklist

1. Appoint / document information officer
2. Maintain processing inventory (clients, officers, CCTV metadata, medical notes)
3. Keep operator agreements and operator processing records
4. Breach response playbook (use incident + audit exports)
5. Review annually against this outline

Demo environments must not hold real personal information without contracts and safeguards.
